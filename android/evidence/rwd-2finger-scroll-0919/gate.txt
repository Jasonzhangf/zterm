## Defect and fix (runtime, not theoretical)

resolveRemoteWindowTouchPairPointerMoveRuntime decided the two-finger commit with the
PER-SAMPLE midpoint delta (state.lastMidX/lastMidY). Real pointer samples on device arrive
at ~4-5 px, so the 8 px threshold was never reached and a normal two-finger swipe emitted
zero remote events. The fix compares CUMULATIVE travel from state.startMidX/startMidY, and
the commit event now dispatches that accumulated travel instead of only the last per-sample
delta (previously the observe-window travel was dropped). Committed scroll updates keep
per-sample deltas.

## Scroll delta trace (runtime level)

Geometry surface 200x100, source 800x600, same-direction vertical two-finger swipe from
clientY 60, 10 samples (temporary probe, removed after the run):

  step=4px idx1 travel=4  mode=twoFingerCandidate events=[]
  step=4px idx2 travel=8  mode=twoFingerScroll    events=[scroll/start/dy=48]
  step=4px idx3 travel=12 mode=twoFingerScroll    events=[scroll/update/dy=24]
  ... idx4..idx10 -> scroll/update/dy=24 each
  step=5px idx1 travel=5  mode=twoFingerCandidate events=[]
  step=5px idx2 travel=10 mode=twoFingerScroll    events=[scroll/start/dy=60]
  step=5px idx3 travel=15 mode=twoFingerScroll    events=[scroll/update/dy=30]
  ... idx4..idx10 -> scroll/update/dy=30 each

Pre-fix the same sequences emitted 0 events and the mode stayed twoFingerCandidate.
The commit event carries the accumulated observe-window travel, later events stay
per-sample, so the emitted sum equals the full gesture travel exactly once (no double count).

Overlay-level check (surface 300x200, target crop 800x560, gesture 130 -> 90 -> 50 = 80 px raw):
  pre-fix : 56 + 56 + 56 = 168  (observe-window sample dropped)
  post-fix: 112 + 56 + 56 = 224 (full 80 px raw travel emitted exactly once)
Three overlay tests asserting an exact commit deltaY were updated 56 -> 112 accordingly.
