# Feature Gates

`docs/feature-registry.json` is the machine-checkable feature gate matrix. This document explains how to apply it.

## Required Flow

1. Pick the `feature_id` before editing code.
2. Confirm the changed files are inside `allowed_paths` for that feature.
3. If a necessary file is not in `allowed_paths`, update the registry first and add or adjust a truth gate explaining the new owner boundary.
4. Run every `required_gates` entry for the feature.
5. For terminal transport, daemon input, buffer/render, schedule, and file transfer changes, also run the terminal regression stack required by `docs/dev-workflow.md`.

## Remote-window quality/gesture amendment gate

The active `2026-08-30-remote-window-quality-gesture-control-amendment.md` is
the canonical contract. Release-time single-finger swipe, zoomed single-finger
local pan, one-second gesture expiry, and queued continuous receive-time refresh
are physically absent from the current runtime and executable gate text:

- default preference is `smooth`; `quality` is selectable; quality is one
  profile containing bitrate, capture dimensions, frame rate, maximum frame
  age, interaction state, and overview budget;
- quality control is single-flight/latest-wins with explicit rejected/timeout
  recovery and two-sample post-apply cooldown; identical profiles are full
  chain no-ops;
- bitrate-only applies sender parameters only; cadence/dimensions/filter
  changes update the existing `SCStream` in place; quality updates never call
  stop/start capture;
- network, host capture/encode, Android decode/render, and latency-only facts
  select one-level cause-specific changes and never reconstruct each other;
- Direct Touch one-finger movement is realtime bounded remote pixel scroll at
  1x and zoomed scale; hold-drag is reliable remote drag; zoomed two-finger
  coherent motion is local pan; 1x two-finger motion is remote scroll; pinch
  is local; five-second and cancel sequences always release remote down;
- reliable input and continuous input use physically separate delivery
  control; 120 Hz move/scroll produces at most 45 continuous wire actions per
  second, pending continuous depth is at most two, and reliable release/key/
  click/barrier records are neither merged nor dropped;
- focus canvas is decoded-frame driven with at most one draw per frame id;
  capture/conversion is latest-frame with at most one pending frame per lane
  and drops frames older than the active profile budget;
- control/retry/revision/health/telemetry never enters video-frame or input
  business payload metadata; terminal mirror/buffer/renderer and screenshot
  frames remain forbidden stream paths.

Required proof is the paired positive/negative matrix in
`docs/testing/remote-window-stream-test-design.md`, registry/import/function/
mainline gates, canonical builds, installed daemon/APK identities, real
Mac+Android route A/B, exact cleanup, and AGY Review PASS.

## Gate Meaning

- `owners`: unique modules that own the feature state or behavior.
- `allowed_paths`: files or directories that may change for that feature.
- `forbidden_paths`: paths that must not be used as shortcut or fallback locations.
- `required_gates`: tests or scripts that must pass before the feature can be reported complete.
- `truth_sources`: docs or skills that define the invariant behind the feature.

## No Fallback Rule

Do not use another feature owner to compensate for a broken owner. If a feature cannot be fixed inside its owner surface, update the registry and truth gates first so the ownership change is explicit and testable.
