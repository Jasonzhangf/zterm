## Daemon stop and pending negotiation

Stop sets an admission-closed flag immediately; both reliable and continuous input reject new work, frame ingress stops, and startup continuation checks that state after every negotiation await. Cancel the original pendingAnswers owner at the admission boundary: clear its existing timer, delete its pending entry, reject its original promise with typed remote_window_stream_answer_cancelled. Do this before waiting for any dependent negotiation continuation, to avoid a stop/answer deadlock. Late answer checks the existing stream's closed/admission state or the existing completed-stream cache and returns that explicit cancellation code, never resolves a stopped start promise. No new independent tombstone registry is required. Ensure rejected start cleanup calls the same session cleanup owner and cannot overwrite a successful stop or restart the peer.

Each resource field is cleared only on successful release. Failures preserve the real reference for retry; successful resources are not retried unnecessarily. Typed stop status released means this stream owns no input leases and no media/session resources. cleanup_failed/failed/unverified carries exact remaining resource identities and errors.
